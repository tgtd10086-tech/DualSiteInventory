# 黑盒铺子双站商品管理中心 — v1.0 开发验证版 1

> **非最终正式版**。基于 v0.8 工程实现 V1.5 计划书的第一批基础功能。Windows 实站采集、CEOACC 多规格、TG 真实群组发布尚未进行端到端验收。

## 本批已经实现的内容

- 新增网站原始类目发现与状态管理：待审核、持续监控、暂停、长期排除。网站分类与自定义项目互相独立。
- 选定类目扫描：只将用户勾选为启用的分类 URL 纳入扫描队列；排除分类不写入商品主数据库。若页面技术上必须加载全站商品，不保证减少实际网络数据传输。
- 只有扫描无失败、未截断且存在有效商品时，才按批次事务写入商品和库存快照；失败扫描保留记录而不写正式库存。
- 原始商品字段与全局/项目改名、改价隔离。
- **售价保护**：项目截图以及 Bot 自动发布一律只接受 `effective_usd`（项目售价→全局售价）；没有自定义售价，拒绝生成图片，**绝不回退网站原价**。
- 自动计算最近24小时、7天、30天观察到的库存减少量；历史不足或最近更新时间过旧显示“数据不足”。每项目可勾选截图展示周期。此数值只是估算，非真实订单。
- 定时任务中文化；支持每 N 小时循环，也支持每天固定 HH:MM 触发（多个时间以英文逗号隔开）。
- 保留白色 Tkinter 导航 UI、原有 Bot 发布与 Windows 构建流程。

## 一次性使用流程

1. 在「网站类目管理」选择站点 →「发现所选网站类目」。
2. 出现分类后多选需要的分类 →「启用选中类目」；其他分类保持待审核或设为长期排除。
3. 前往「全站采集」或「采集任务管理」对启用类目进行扫描。
4. 在「商品数据库」检查商品行，建立「项目管理」项目、添加商品，设置项目专属显示名称及销售价。
5. 在「截图模板」选择项目及 24h/7d/30d 指标，确认不含网站原价。
6. 需要发 Telegram 时，先保存 Bot Token，指定目标 TG 群组/频道，并做小规模测试。

## 尚需实测和完善（不能视为已验收）

- CEOACC 与 FB1314 网站的真实类目识别是否完整；目前类目发现依赖公开 `<a href>` 导航，动态下拉按钮不一定包含可识别的分类 URL。
- 每个分类的虚拟滚动、实际停止信号、商品标识与规格的可靠性；如果商品没有稳定原始 ID，原始名称哈希不是可靠长期标识。
- 类目总数和商品覆盖率核对（两次完整现场扫描）；无法验证时不应将扫描称为全站完整。
- Windows 端 FlClash 环境的实际采集速度、代理及权限设置。
- 每日固定任务执行时间在 Windows 夏令时切换与长时间休眠恢复时的边界行为。
- Telegram 多群组独立配置、个人账号授权登录尚未集成；目前沿用单条 Bot 发布任务。
- 专业化报价模板与完整 UI 的视觉细节仍需继续实现。

## 升级与安全

SQLite 数据库采用追加字段及新表的方式迁移。**升级之前务必备份**原版 `inventory.sqlite3` 及设置文件。
Windows 安装程序由 GitHub Actions 打包；ZIP 内不是已经构建好的 EXE。
采集器只访问公开商品列表，不执行购买、登录绕过、验证码绕过。
